# 注释式编码陪伴者 · GoLand MVP 设计文档

> 状态：方案讨论收口草案 v0.1  
> 目标平台：GoLand / Go  
> 范围：个人自用 MVP，**单文件内**修改  
> 产品原则：无窗口；注释即指令；失败可见、可回滚、可撤销

---

## 1. 一句话定义

用户把意图写进 Go 注释（`// ai：…`），AI 读取注释与当前函数，直接写出/补全/修改函数体，
处理完成后短暂提示，并把指令注释归一化成普通文档注释。**全程不打开聊天窗口。**

---

## 2. 目标与非目标

### 2.1 MVP 目标

1. 在 GoLand 中扫描修改过的 Go 文件，识别 `// ai：` 指令注释。
2. 对指令所附着的函数，读取上下文并生成/补全/修改函数体。
3. 只修改**当前文件**，不跨文件。
4. 生成结果经过 gofmt 与编译检查；失败则回滚，不留半成品。
5. 处理成功后把 `ai：` 指令归一化为普通文档注释。
6. 遇到歧义/冲突时，用 `// ai？` 注释 + 光标附近 inlay 向用户提问。
7. 所有编辑可撤销；同一文件内的 AI 改动合成一次 undo。
8. 侧边栏作为状态/配置仪表盘，不承载对话。

### 2.2 非目标（MVP 不做）

- 跨文件修改、跨文件更新调用点（P1）
- 签名变更波及外部文件（MVP 遇到外部引用时停止并询问）
- review 模式、任务模式、接入 CLI
- 多语言（只做 Go）
- Ayane 身份/记忆/契约接入（MVP 独立，留接口）
- 注释位置扩展（函数体内、同行、块级、选区）
- 泛型函数、匿名函数
- 多 Agent、历史对话面板、信任等级 UI
- 自动添加 import（MVP 先问，信任等级之后放开）
- 自动修改「别处」的 bug（只提示，不许可不改）

### 2.3 成功标准

- 用户写一个空函数 + `ai：` 注释，保存/停顿后几秒内得到可编译的函数体。
- 用户写一半的函数 + `ai：` 注释，AI 能在保留已有代码的前提下继续/修改。
- AI 发现问题时不会静默乱改：提问或提示，用户可拒绝。
- 编译失败时原文件恢复原样，用户清楚知道失败原因。
- 用户不需要维护版本号、hash、状态文件或额外语法。

---

## 3. 核心原则

1. **注释即指令**：`ai：` 是唯一的用户→AI 入口；不弹聊天窗口。
2. **单文件**：MVP 内 AI 的所有编辑只发生在当前文件。
3. **最小改动**：保留用户已写的代码、风格和注释；只改注释要求的部分。
4. **先说明再动**：编译错误可自动修并提示；逻辑/用法错误先问；风格只建议。
5. **失败不静默**：超时、模型错误、编译失败、歧义，都必须可见。
6. **可回滚**：编译失败回滚；所有改动可 undo。
7. **账本对用户不可见**：round/hash/状态存内部，不写进注释让用户维护。
8. **串行、从上到下**：同一时间只有一个 AI 任务。

## 4. 注释协议

### 4.1 用户指令：`// ai：…`

**语法**

- 前缀：`ai:` 或 `ai：`（全角/半角都认），大小写不敏感；`//ai：` 无空格也认。
- 只认 Go 的 `//` 行注释与 `/* */` 块注释。
- 行注释：
  - `ai：` 所在行 + **其下连续的 `//` 行** = 指令正文；
  - 遇到空行或非注释行截止；
  - `ai：` **上面的行** = 方法说明 / 注入的临时上下文（AI 必须读取并保留，不作为指令动作）。
- 块注释：
  - 只有**首行首处**出现 `ai：` 时才整块作为指令；
  - `ai：` 出现在后面的块注释不认。
- 一个函数同一时间只认**一条** `ai：` 指令；以注释块中第一条 `ai：` 为准，后续行算指令正文。

**位置（MVP）**

- 注释块必须**紧邻函数声明上方**（中间不隔空行）。
- 只支持命名函数与方法（带 receiver）；泛型函数、匿名函数不处理。
- 不满足位置/类型条件时：忽略 + 状态栏轻提示，不生成。

**多条注释示例**

```go
// add 返回两个整数的和。
// 注意：不要处理负数溢出。
// ai：为我实现两数相加，返回值用 int
func add(a, b int) int {
}
```

- 上面两行 = 方法说明/上下文；
- `ai：` 行 = 指令起点；
- 指令正文可继续写在下面连续的 `//` 行里。

### 4.2 AI 提问：`// ai？…`

- AI 需要用户确认/补充时，写一条 `ai？` 注释在**原指令/函数附近**。
- `ai？` 是 AI 拥有的注释：解决后 AI 自己删除；用户不需要手动清理。
- 同时，在**当前光标附近**显示一条轻量 inlay：「有 1 个 AI 提问，在函数上方」；
  inlay 只负责提醒/跳转，权威问题在 `ai？` 注释里。
- 用户回答 = **编辑原 `ai：` 注释**；不是新增 `ai：`，也不是直接改代码。

### 4.3 回答与状态规则

| 动作 | 是否算回答 | 说明 |
| --- | --- | --- |
| 编辑原 `ai：` 注释内容 | 是 | 唯一正式回答方式；按注释版本变化触发 |
| 新增第二条 `ai：` | 否 | MVP 不允许；以第一条为准 |
| 直接改函数体/签名 | 否 | AI 不把代码改动当回答 |
| 直接改代码消掉了问题 | 不算回答 | AI 可把问题标记为「已失效」并清掉，但不继续执行 |

- 用户想提新需求：继续改原 `ai：` 注释内容。
- 用户想重跑：把归一化后的注释重新加上 `ai：` 前缀，或改内容。
- AI 执行成功后：`ai：` 归一化成普通文档注释（见 §8），标记消失，自然不再重复触发。

### 4.4 边界情况

- `ai：` 在函数上方但函数无法解析：跳过 + 状态栏提示。
- 文件有严重语法错误：不生成，提示先修语法；不硬猜。
- 注释块与函数之间有空行：MVP 视为未附着，忽略 + 提示。
- 泛型/匿名函数：忽略 + 提示「暂不支持」。
- 同一文件多个函数带 `ai：`：串行处理，从上到下。

## 5. 触发与扫描调度

### 5.1 触发信号

采用「文档事件 + 固定轮询」混合：

- 监听打开文档的编辑事件，记录修改戳。
- 固定周期（建议 1s）扫描**打开/修改过的项目文件**。
- 检测到修改后等待 **1~1.5s 空闲** 再提取任务，避免打字中途触发。
- 排除目录：`.git`、`vendor`、`node_modules`、构建产物、配置的忽略目录。
- 只扫描 `.go` 文件。
- 记录文件内容哈希，内容没变不重复处理。
- **忽略 AI 自己写入产生的事件**，防止回环。

### 5.2 任务条件

一个函数进入队列需同时满足：

1. 文件是项目内 `.go` 文件，且处于打开/修改状态；
2. 函数上方有合法的 `ai：` 注释块；
3. 函数可被 PSI 定位（命名函数/方法）；
4. 该注释版本此前未处理过；
5. 该函数当前没有未解决的 `ai？` 提问；
6. 插件处于启用状态。

### 5.3 调度规则

- **串行**：同一时间只处理一个任务。
- **从上到下**执行（按文件内位置排序）。
- 应用编辑时使用快照偏移，或从下到上落盘，避免前面的编辑顶偏后面的位置。
- 每处理完一个函数重新读取一次文档，再处理下一个。
- 文件关闭/插件禁用/用户取消：取消当前及排队任务。
- 侧边栏显示：扫描中 / 空闲 / 队列 N / 当前处理哪个函数。

## 6. 生成与编辑规则

### 6.1 上下文

AI 生成时读取：

- 函数签名、当前函数体、函数上方的说明注释与 `ai：` 指令；
- 文件 package、imports、同文件相关类型/常量；
- 同文件内的调用点（用于签名变更判断）；
- 当前编译诊断（基线错误）；
- 项目 Go 版本/模块信息（能拿到时）。

MVP 不上传跨文件内容；只读当前文件。

### 6.2 生成输出

AI 返回结构化结果：

- 新的函数体（或函数级 patch）；
- 归一化后的文档注释；
- 可选：需要用户回答的问题；
- 可选：改动说明（用于完成提示）。

### 6.3 编辑规则

- **最小改动**：保留用户已写代码；只补/只改注释要求的部分。
- 只改当前函数；函数外的改动仅限：
  - 同文件 import 的增删（MVP 先问，不自动加）；
  - 同文件调用点（仅当签名变更且引用都在当前文件内）。
- 不修改用户的说明注释；归一化只处理 `ai：` 指令部分。
- 不删除 `ai：` 上面的上下文行。
- 不做风格重排；不做无关重构。
- 格式化：对改动范围执行 gofmt；不整文件重排。
- 编码：UTF-8；保留用户的注释语言（中文/英文）。

### 6.4 签名变更策略（MVP）

- 默认：不改签名；注释与签名冲突时，用 `ai？` 询问。
- 用户通过 `ai：` 明确要求改签名时：
  - 若函数引用**全部在当前文件内**：允许改签名，并更新同文件调用点；
  - 若存在**外部文件引用**：MVP 停止并询问，不自动改（跨文件属 P1）。
- 导出 API 的签名变更：必须显式确认；提示兼容性风险。

### 6.5 错误处理策略

| 错误类型 | 处理 |
| --- | --- |
| 语法/编译错误 | AI 可自动修；完成后在提示里列出「顺手修了 X，因为 Y」，可 undo |
| 逻辑/用法错误 | 先不改；`ai？` 给出原因与建议，用户确认后再改 |
| 风格/习惯 | 只提示，不自动改 |
| 别处的 bug | 只提示，未许可不改；去重、只报高置信度、最多 N 条 |
| 需要新 import | MVP 先用 `ai？` 询问，不自动加 |

### 6.6 用户中途输入

- 使用文档版本号/修改戳检测。
- 应用前重新读取当前函数，把补丁 rebase 到最新内容。
- 不覆盖用户新写的行。
- 冲突（用户改了同一行/同一区域）：不硬合并，提示「重试 / 放弃」。
- 修复循环期间用户持续输入：等短暂空闲再应用。

## 7. 编译验证、修复循环与回滚

### 7.1 基线

- 编辑前先记录当前文件编译错误集合（基线）。
- 用于区分「原本就有的错误」与「AI 引入的错误」。

### 7.2 修复循环

- 最多 **5 轮**：生成 → gofmt → 编译 → 有错则带错误信息修复。
- 总时间上限：**60s**（可配置）。
- 无进展停止：连续一轮错误数量没有减少，停止。
- 侧边栏显示「第 n/5 轮修复」。

### 7.3 回滚

- 触发条件：5 轮后仍有**新增**编译错误（相对基线）。
- 回滚内容：函数体、归一化注释、同文件 import/调用点改动。
- 回滚到 AI 编辑前的快照；保留原 `ai：` 注释，便于用户修改后再试。
- 如果原本就编译不过：不把责任归给 AI；回滚到原样并说明「文件原本存在错误」。
- 失败摘要：错误列表 + 最后一次尝试（侧边栏/inlay 可查看，不弹窗）。

### 7.4 撤销

- 同一文件内：body + 归一化 + import/调用点改动合成一个命令，**一次 Ctrl+Z 全回**。
- MVP 单文件，因此不需要跨文件事务撤销。
- 用户之后自己输入的内容在 undo 栈上方；Ctrl+Z 先撤用户输入，再撤 AI，属正常行为。

## 8. 注释归一化

### 8.1 时机

- 仅在生成成功且编译通过后执行。
- 失败、回滚、等待回答时：保留 `ai：` 指令，不归一化。

### 8.2 规则

- 把 `ai：` 指令正文转换成普通文档注释（去掉 `ai：` 标记）。
- **保留 `ai：` 上面的方法说明/上下文**；把指令语义合并进去，避免重复。
- 保留原注释语言（中文/英文）。
- 语义保留即可，措辞由 AI 按 Go doc 习惯重写。
- 文档必须反映**最终代码**；不得写入代码里没有的行为。
- 如函数上方已有文档注释：合并，不产生两条重复文档。
- 块注释：保留块注释形式或改为 `//`，以可读为准；不丢失语义。
- 归一化与函数体改动在同一次编辑命令中，一次 undo 全回退。

### 8.3 提示

- 归一化完成后显示短提示：「已把指令整理为文档注释 · 第 N 轮」（3~5s 淡出）。

## 9. 提问、排队与回答

### 9.1 呈现

- **权威问题**：`// ai？…` 注释，写在原指令/函数附近，AI 拥有，解决后删除。
- **光标附近**：轻量 inlay「有 1 个 AI 提问，在函数上方」，点击跳转。
- 状态栏：待答问题数量。
- 不弹窗、不抢焦点、不打开聊天面板。

### 9.2 排队

- 一个函数同一时间最多一个待答问题；多个问题合并成一条 `ai？`（分点写）。
- 多个函数的问题按文件位置从上到下排序。
- 状态栏显示「有 N 个待答」；点击跳到下一个（循环）。
- 待答问题不阻塞其它函数；AI 可继续处理无问题的函数。
- 待答状态由 `ai？` 注释持久化；重启 IDE 后仍在。
- 用户忽略：问题一直挂着，不反复提醒、不重复生成。

### 9.3 回答

- 用户编辑原 `ai：` 注释内容（不是新增一条）。
- 保存/空闲后，AI 读取最新注释版本，视为新指令；若存在待答问题，视为对该问题的回答。
- AI 应用后删除自己的 `ai？` 注释，并归一化 `ai：`。
- 用户直接改代码不算回答；若代码改动让问题失效，AI 可将 `ai？` 标记为「已失效」并清掉。
- `ai？` 的写入/删除与本次编辑同属一个事务，undo 一起回退。

### 9.4 示例

```go
// add 返回两个整数的和。
// ai：为我实现两数相加
func add(a, b int) {
}
```

AI 发现签名没有返回值，写：

```go
// add 返回两个整数的和。
// ai：为我实现两数相加
// ai？注释要返回结果，但当前签名没有返回值。改成 func add(a, b int) int 吗？请改上面的 ai： 注释回答。
func add(a, b int) {
}
```

用户把 `ai：` 那行改成：

```go
// ai：改，返回 int
```

AI 应用后：

```go
// add 返回两个整数的和。
func add(a, b int) int {
    return a + b
}
```

`ai？` 被删除，提示淡出。

## 10. 状态与持久化

### 10.1 存储位置

- 使用 IntelliJ 项目级 `PersistentStateComponent`（workspace 状态，位于 `.idea`，默认不进 git）。
- 不写用户仓库的业务文件，不污染代码。

### 10.2 记录内容

按「文件路径 + 函数标识（receiver/name/参数类型）」存储：

| 字段 | 用途 |
| --- | --- |
| `round` | 该函数第几轮 AI 交互，用于提示/日志 |
| `lastInstructionText` 或 `lastInstructionHash` | 判断注释是否变化（触发键） |
| `lastResultHash` | 判断结果是否变化/重复 |
| `status` | 成功/失败/等待回答/已回滚 |
| `timestamp` | 清理与排障 |

- 实际判断允许用「上次注释文本」或 hash；MVP 推荐直接存文本，便于调试；量大了再换 hash。
- 待答问题不重复存状态：`ai？` 注释本身就是持久化。

### 10.3 生命周期

- 文件重命名/移动：MVP 尽力用 VFS 监听重新关联；失败则当作新函数处理（归一化后一般不会重复触发）。
- 切分支/外部改动：比较当前注释文本；不匹配则视为新指令。
- 多窗口：项目级状态共享。
- 删除文件：清理对应记录。
- 提供 reset（清空状态）；状态丢失不应导致 AI 乱写：没有 `ai：` 标记就不会触发。
- 容量：限制条目数；定期清理过期记录。

## 11. 失败与边界

统一原则：**任何失败都必须可见；能回滚就回滚；不要静默。**

| 场景 | 行为 |
| --- | --- |
| 文件无法解析 | 跳过 + 状态栏提示「先修语法」 |
| 函数无法定位 | 跳过 + 提示 |
| `ai：` 位置不合法 | 忽略 + 轻提示 |
| 泛型/匿名函数 | 忽略 + 提示「暂不支持」 |
| 模型超时/报错 | 取消任务；保留原代码；侧边栏/inlay 显示原因 |
| 编译失败（新增错误） | 回滚；保留 `ai：`；显示错误摘要 |
| 用户输入冲突 | 不硬合并；提示重试/放弃 |
| 文件只读/VCS 冲突 | 跳过 + 提示 |
| 插件禁用/文件关闭 | 取消任务 |
| 多次失败 | 保留 `ai：`，用户可修改指令后重试；不自动重跑 |

## 12. UI/UX

### 12.1 Inlay

- 生成中：「正在写…」（轻量、不抢焦点）。
- 完成：「写完了 · 第 N 轮 · 一句理由」，3~5s 淡出，点击可查看/撤销。
- 提问：常驻，直到回答/失效/手动关闭。
- 失败：常驻，显示原因 + 重试/撤销。
- 位置：锚定在函数/原注释附近；光标在函数内时看起来就在光标附近。
- 不写进文件、不触发文件刷新。

### 12.2 状态栏

- 显示：扫描状态、队列长度、待答问题数量。
- 点击跳转到对应函数/`ai？` 注释。
- 不弹窗。

### 12.3 侧边栏（仪表盘）

- 当前状态：扫描 / 空闲 / 生成 / 修复 n/5 / 等待回答 / 回滚。
- 队列与当前文件任务。
- 待答问题列表（点击跳转）。
- Provider 配置：base URL、API key、model。
- 日志（本地，可清理；代码/prompt 可见，提示敏感信息风险）。
- 开关、reset、忽略目录配置。
- 信任等级入口（P1 占位）。
- **不承载对话**：对话只发生在注释里。

### 12.4 其他

- `ai：` 输入可通过 live template 快速补全（键入 `ai` 展开注释模板）。
- 提示语气：MVP 保持简洁、工具化；后续接入 Ayane 人格再调整。
- 不提供完整 diff 窗口；MVP 用 undo + inlay 的「查看改动」轻量入口，完整 diff 后续再加。

## 13. 引擎、模型与后端

### 13.1 形态

- MVP 独立插件，不接 Ayane。
- 预留两个接口：
  - `CodingEngine`：生成 / 修复 / 取消 / 流式事件；
  - `WorkspaceAdapter`：读取函数与上下文、应用编辑、格式化、编译诊断、undo 分组。
- 引擎先在插件进程内运行（后台协程），以后可抽成本地服务或接 Agent Service。

### 13.2 模型

- BYOK：用户在侧边栏配置 OpenAI-compatible 的 base URL、API key、model。
- 不硬编码供应商；不内置 key；key 存 IDE 凭据存储，不写日志。
- MVP 用非流式请求；后续可加流式。
- 请求超时、取消、重试上限可配置。

### 13.3 日志

- 默认本地留存，可配置保留时长与清理。
- 默认不上报遥测。
- 日志可能包含代码与 prompt：提示用户注意敏感信息；API key 绝不写日志。
- 侧边栏可查看最近任务日志，便于排障。

---

## 14. 信任等级（P1 占位）

MVP 先按保守策略；后续用信任等级控制自动动作：

| 等级 | 能力 |
| --- | --- |
| L0 | 只提示，不改 |
| L1 | 自动格式化、自动加 import |
| L2 | 自动修编译错误 |
| L3 | 自动改签名 + 同文件调用点 |
| L4 | 跨文件调用点更新 |

MVP 默认：编译错误自动修 + 提示；import 先问；签名变更先问；别处 bug 只提示。

---

## 15. MVP 验收场景

1. 空函数 + `ai：` → 生成可编译函数体。
2. 写一半的函数 + `ai：` → 保留已有代码，继续/修改。
3. 完整函数 + `ai：` → 按要求修改。
4. 签名冲突 → `ai？` 提问 → 用户改 `ai：` 回答 → 应用 + 归一化。
5. 编译失败 → 5 轮修复 → 仍失败 → 回滚，原文件恢复，`ai：` 保留。
6. Ctrl+Z 一次撤销 body + 归一化 + import/同文件调用点。
7. 同文件多个 `ai：` → 串行、从上到下、位置不漂移。
8. 修改文件 → 轮询+空闲检测触发；不重复、不回环。
9. 外部引用存在时改签名 → 停止并询问，不跨文件。
10. 侧边栏可配置 provider、查看状态与日志。

### 15.1 观察指标

- 编译通过率；
- 一次接受率（生成后 N 分钟内未 undo/修改）；
- 提问率 / 用户回答率；
- 延迟 p50 / p95；
- token 消耗；
- 回滚率。

## 17. 待定与风险

### 17.1 待定

- `ai：` 注释块与函数之间是否允许空行（MVP 当前严格：不允许）。
- 块注释归一化后保留块形式还是转 `//`。
- 多个 `ai：` 行的最终处理（MVP 以第一条为准）。
- 状态 key 在文件重命名后的恢复策略（MVP 尽力而为）。
- 侧边栏字段与轮询/空闲默认值需实测调整。
- 信任等级的具体门槛。
- 完整 diff 的呈现方式（后续）。

### 17.2 风险

- 模型对 Go 惯用法/错误处理的生成质量；
- GoLand PSI/undo/编译 API 的版本兼容性；
- 用户边写边触发时的合并冲突；
- 注释语义与签名冲突的判定准确性；
- 轮询扫描的性能与误触发；
- 代码隐私与日志留存；
- 「无窗口」下复杂问题的解释空间有限。

## 18. 决策记录

| 决策 | 结论 |
| --- | --- |
| 注释位置 | MVP 仅函数上方 |
| 触发方式 | `ai：` 注释 + 轮询/空闲检测 |
| 空函数体要求 | 不要求，半成品/完整代码都可 |
| 归一化 | 成功后转普通文档注释，保留语义与上下文 |
| 提问形式 | `ai？` 真正注释 + 光标附近 inlay |
| 回答方式 | 编辑原 `ai：` 注释；直接改代码不算回答 |
| 待答排队 | 一函数一问题，合并；从上到下，状态栏计数 |
| 签名变更 | 仅当前文件引用时允许；外部引用停止并询问 |
| 错误策略 | 编译自动修+提示；逻辑先问；风格只提示；别处只报告 |
| 修复轮数 | 5 轮 / 60s / 无进展停止 |
| 编译失败 | 回滚到编辑前；保留 `ai：` |
| undo | 同文件一次 Ctrl+Z；MVP 无跨文件事务 |
| 调度 | 串行、从上到下；快照偏移应用 |
| 模型 | BYOK，OpenAI-compatible，用户配置 |
| 日志 | 本地留存，可清理；无遥测；key 不落日志 |
| MVP 范围 | 单文件、单函数；跨文件 P1 |
